# useApi

`useApi` is a Nuxt 4 `createUseFetch` composable factory designed for SSR-friendly data fetching. It configures default API base routes, attaches session Bearer tokens, and handles auto-logout on unauthenticated `401` errors.

## Features

- **Setup Context Safe**: Defined using function syntax to prevent import-time context errors.
- **Proxy Support**: Auto-routes to `/api/proxy` when `NUXT_PUBLIC_ENABLE_PROXY` is set.
- **Bearer Token Auth**: Opt-in token injection by passing `{ auth: true }`.
- **401 Auto Logout**: Automatically clears cookie session and navigates to `/login` on auth failure.

## Usage Example

### Authenticated Request

```ts
const { data: user, status, refresh } = await useApi("/user/profile", {
  auth: true
})
```

### Query Parameters

```ts
const { data: products } = await useApi("/products", {
  query: { category: "electronics" }
})
```

## Implementation Code

### 1. Declarative Composable (`app/composables/useApi.ts`)

`useApi` provides declarative SSR-friendly data fetching following the Nuxt 4 `createUseFetch` pattern. 

#### Design Details & Rationale

- **`useApi` vs `$api`**: `useApi` is used for setup-phase page data fetching (returning `{ data, status, refresh }`). The imperative companion `$api` plugin is used in event handlers and mutations.
- **Function Factory Syntax**: Defined as a function `createUseFetch((callerOptions = {}) => ...)` so `useRuntimeConfig()` and `useUserSession()` execute during component setup. A static object literal would evaluate at module import time and throw errors.
- **Base URL Precedence**: Evaluates `callerOptions.baseURL ?? ...` first to allow per-call overrides (e.g. local `/api/` endpoints) before defaulting to proxy or external API base URLs.
- **Header Merging**: Mutates `options.headers` inside `onRequest` rather than declaring a top-level factory `headers` object, preventing shallow merge conflicts with per-call headers.
- **Nuxt Context Preservation**: Because lifecycle interceptors may execute outside Nuxt's synchronous context, composable calls (`fetchSession()`, `clearSession()`, `navigateTo()`) are wrapped in `nuxtApp.runWithContext()`.

```ts
export const useApi: typeof useFetch = createUseFetch((callerOptions = {}) => {
  const config = useRuntimeConfig();
  const nuxtApp = useNuxtApp();
  const {
    session,
    fetch: fetchSession,
    clear: clearSession,
  } = useUserSession();

  return {
    baseURL: (callerOptions.baseURL ??
      (config.public.enableProxy
        ? "/api/proxy"
        : config.public.apiBase)) as string,

    async onRequest({ options }) {
      options.headers.set("Accept", "application/json");

      const { auth } = options as { auth?: boolean };
      if (!auth) return;

      if (!session.value) {
        await nuxtApp.runWithContext(() => fetchSession());
      }
      if (session.value?.token) {
        options.headers.set("Authorization", `Bearer ${session.value.token}`);
      }
    },

    async onResponseError({ response }) {
      if (
        response.status === 401 ||
        (response._data as { message?: string })?.message === "Unauthenticated"
      ) {
        await nuxtApp.runWithContext(async () => {
          await clearSession();
          await navigateTo("/");
        });
      }
    },
  };
});
```

### 2. Imperative Plugin Companion (`app/plugins/api.ts`)

Provides `$api`, a pre-configured `$fetch` instance created once with runtime base URLs, automatic Bearer authentication, and global 401 unauthenticated logout handling.

#### Usage

```ts
const { $api } = useNuxtApp()

// Client-side imperative request
await $api('/profile', { auth: true })

// SSR-safe data fetching using custom $fetch
await useFetch('/courses', { $fetch: $api })
```

```ts
export default defineNuxtPlugin((nuxtApp) => {
  const {
    session,
    fetch: fetchSession,
    clear: clearSession,
  } = useUserSession();
  const config = useRuntimeConfig();

  const baseURL = config.public.enableProxy
    ? "/api/proxy"
    : (config.public.apiBase as string);

  const api = $fetch.create({
    baseURL,
    headers: { Accept: "application/json" },

    async onRequest({ options }) {
      const { auth } = options as { auth?: boolean };
      if (!auth) return;

      if (!session.value) {
        await nuxtApp.runWithContext(() => fetchSession());
      }

      if (session.value?.token) {
        options.headers.set("Authorization", `Bearer ${session.value.token}`);
      }
    },

    async onResponseError({ response }) {
      if (
        response.status === 401 ||
        (response._data as { message?: string })?.message === "Unauthenticated"
      ) {
        await nuxtApp.runWithContext(async () => {
          await clearSession();
          await navigateTo("/");
        });
      }
    },
  });

  return { provide: { api } };
});
```

### 3. Configuration (`nuxt.config.ts`)

```ts
export default defineNuxtConfig({
  modules: ["nuxt-auth-utils"],
  runtimeConfig: {
    public: {
      apiBase: process.env.NUXT_PUBLIC_API_BASE || "https://api.example.com",
      enableProxy: process.env.NUXT_PUBLIC_ENABLE_PROXY === "true",
    },
  },
});
```
