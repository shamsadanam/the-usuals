# useApi

`useApi` is a Nuxt 4 `createUseFetch` composable factory designed for SSR-friendly data fetching. It configures default API base routes, attaches session Bearer tokens, and handles auto-logout on unauthenticated `401` errors.

## Prerequisites

### 1. External Modules & Libraries
- **[`nuxt-auth-utils`](https://github.com/atinux/nuxt-auth-utils)**: Required for session state and Bearer token management via `useUserSession()`.
  ```bash
  pnpm add nuxt-auth-utils
  ```
  Register in `nuxt.config.ts`:
  ```ts
  export default defineNuxtConfig({
    modules: ["nuxt-auth-utils"],
  });
  ```

### 2. Environment Variables & Runtime Config
- **Session Secret**: Add a 32+ character secret to `.env`:
  ```env
  NUXT_SESSION_PASSWORD="a-long-random-string-at-least-32-characters"
  ```
- **Runtime Config**: Configure API base URL and proxy toggle in `nuxt.config.ts`:
  ```ts
  export default defineNuxtConfig({
    runtimeConfig: {
      public: {
        apiBaseUrl: process.env.NUXT_PUBLIC_API_BASE_URL || "https://api.example.com",
        enableProxy: process.env.NUXT_PUBLIC_ENABLE_PROXY === "true",
      },
    },
  });
  ```

### 3. Server Proxy (Optional)
- Catch-all proxy route (`server/api/proxy/[...].ts`) or Nitro `routeRules` proxy if running with `enableProxy: true`.

## Features

- **Setup Context Safe**: Defined using function syntax to prevent import-time context errors.
- **Proxy Support**: Auto-routes to `/api/proxy` when `NUXT_PUBLIC_ENABLE_PROXY` is set.
- **Bearer Token Auth**: Opt-in token injection by passing `{ auth: true }`.
- **401 Auto Logout**: Automatically clears cookie session and navigates to `/login` on auth failure.

## Usage Example

### Authenticated Request

```ts
const { data: user, status, refresh } = await useApi("/user/profile", {
  auth: true
})
```

### Query Parameters

```ts
const { data: products } = await useApi("/products", {
  query: { category: "electronics" }
})
```

## Implementation Code

### 1. Declarative Composable (`app/composables/useApi.ts`)

`useApi` provides declarative SSR-friendly data fetching following the Nuxt 4 `createUseFetch` pattern. 

#### Design Details & Rationale

- **`useApi` vs `$api`**: `useApi` is used for setup-phase page data fetching (returning `{ data, status, refresh }`). The imperative companion `$api` plugin is used in event handlers and mutations.
- **Function Factory Syntax**: Defined as a function `createUseFetch((callerOptions = {}) => ...)` so `useRuntimeConfig()` and `useUserSession()` execute during component setup. A static object literal would evaluate at module import time and throw errors.
- **Base URL Precedence**: Evaluates `callerOptions.baseURL ?? ...` first to allow per-call overrides (e.g. local `/api/` endpoints) before defaulting to proxy or external API base URLs.
- **Header Merging**: Mutates `options.headers` inside `onRequest` rather than declaring a top-level factory `headers` object, preventing shallow merge conflicts with per-call headers.
- **Nuxt Context Preservation**: Because lifecycle interceptors may execute outside Nuxt's synchronous context, composable calls (`fetchSession()`, `clearSession()`, `navigateTo()`) are wrapped in `nuxtApp.runWithContext()`.

```ts
export const useApi: typeof useFetch = createUseFetch((callerOptions = {}) => {
  const config = useRuntimeConfig();
  const nuxtApp = useNuxtApp();
  const {
    session,
    fetch: fetchSession,
    clear: clearSession,
  } = useUserSession();

  return {
    baseURL: (callerOptions.baseURL ??
      (config.public.enableProxy
        ? "/api/proxy"
        : config.public.apiBaseUrl)) as string,

    async onRequest({ options }) {
      options.headers.set("Accept", "application/json");

      const { auth } = options as { auth?: boolean };
      if (!auth) return;

      if (!session.value) {
        await nuxtApp.runWithContext(() => fetchSession());
      }
      if (session.value?.token) {
        options.headers.set("Authorization", `Bearer ${session.value.token}`);
      }
    },

    async onResponseError({ response }) {
      if (
        response.status === 401 ||
        (response._data as { message?: string })?.message === "Unauthenticated"
      ) {
        await nuxtApp.runWithContext(async () => {
          await clearSession();
          await navigateTo(useAppConfig().auth.afterLogoutRoute);
        });
      }
    },
  };
});
```

### 2. Imperative Plugin Companion (`$api`)

While `useApi` is designed for declarative data fetching during component setup, its companion plugin provides `$api` (`useNuxtApp().$api`) for event handlers, mutations, and form submissions.

For the complete standalone source code, interceptor caveats, and usage examples, see the dedicated **[$api Plugin](/nuxt/plugins/api)** documentation.

### 4. Simple Proxy via Route Rules (`nuxt.config.ts`)

For simple pass-through scenarios that do not require custom server middleware, header inspection, or error interception, Nuxt supports declarative proxying directly in `routeRules`:

```ts
export default defineNuxtConfig({
  routeRules: {
    "/api/proxy/**": {
      proxy: `${process.env.NUXT_PUBLIC_API_BASE_URL}/**`,
    },
  },
});
```

Nitro handles this at the engine level without requiring any custom server files, and edge deployment providers can compile it directly into CDN-level rewrites.

### 5. Advanced / Custom Nitro Proxy Catch-All Route (`server/api/proxy/[...].ts`)

When programmatic control is required (such as runtime validation, header transformations, custom error responses, or dynamic target resolution), implement a custom Nitro server route using `proxyRequest`:

#### Design Details & Rationale

- **CORS Bypass & Origin Shielding**: Keeps browser communication strictly on the same origin (`/api/proxy/...`), eliminating third-party CORS issues and protecting internal service endpoints.
- **Header & Payload Forwarding**: Nitro's `proxyRequest` transparently streams request bodies (JSON, form-data, blobs) and passes along client headers (such as `Authorization: Bearer <token>`) while stripping hop-by-hop headers.
- **Prefix Stripping & Query Concatenation**: Extracts the full URL via `getRequestURL(event)`, strips the `/api/proxy` prefix, and appends `url.search` to construct the target upstream URL.

```ts
export default defineEventHandler(async (event) => {
  const config = useRuntimeConfig();
  const url = getRequestURL(event);

  if (!config.public.apiBaseUrl) {
    throw new Error("apiUrl is not defined in runtime config");
  }

  // Remove /api/proxy prefix only
  const path = url.pathname.replace("/api/proxy", "");

  // Build final URL: base + path + query
  const targetUrl = config.public.apiBaseUrl + path + url.search;

  // This forwards:
  // - HTTP method
  // - Headers
  // - Body (JSON, form-data, etc.)
  // - Query params
  return proxyRequest(event, targetUrl);
});
```
